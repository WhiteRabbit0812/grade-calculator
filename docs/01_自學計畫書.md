# 軟體工程 自主學習計畫書

- 課程：軟體工程（115 學年度第 1 學期）
- 學號／姓名：＿＿＿＿＿＿＿＿
- 自學主題：為自己以前寫的程式補上單元測試，並用 GitHub Actions 做自動化測試

## 一、主題與學習動機

大一程式設計課的時候，我寫過一個小工具：讀進一份「姓名,分數」的 CSV 檔，算出每個人的等第、GPA 和全班平均。那時候我只拿四、五筆資料跑過一次，看結果好像沒問題就交了，完全沒想過要寫測試。

這學期上到軟體測試和持續整合，我才開始想：如果現在有人問我這支程式在各種情況下都對嗎，我其實答不出來。像是剛好 60 分算不算及格、檔案最後多一行空白會不會出錯，我都沒有試過。

所以我想拿這支自己寫的小程式來練習。它只有幾十行，我看得懂每一行在做什麼，比較能專心在「測試」本身，而不是花時間理解別人的程式。這個主題也剛好是老師列的參考範例中的兩項：為既有程式補測試並分析覆蓋率，以及用 GitHub Actions 建立自動化測試。

## 二、想回答的問題或預期達成的目標

我想透過這次自學回答三個問題：

1. 幫一支「看起來能跑」的程式補測試，到底能不能找到我原本沒發現的錯？
2. 測試覆蓋率要多少才算夠？覆蓋率高是不是就代表程式沒問題？
3. GitHub Actions 要怎麼設定，才能每次上傳程式碼就自動跑測試？

希望做完之後能達到幾件事：會用 pytest 寫一般的測試、參數化測試和「預期會丟出錯誤」的測試；程式裡每個函式都有測試，而且有測到邊界值和錯誤輸入；修好測試抓到的問題，讓測試全部通過；覆蓋率至少 90%，並能說明沒覆蓋到的地方為什麼可以接受；最後讓 GitHub 在我每次 push 時自動幫我跑測試。

## 三、學習方法與使用資源

我打算先照著官方文件把範例做一遍，有概念之後再套用到自己的程式。過程中有兩個原則：

第一，先寫測試、把「修改前」的失敗結果存下來，再去改程式。這樣最後可以拿前後結果比較，也能當作學習證據。

第二，每完成一個段落就用 Git commit 一次，讓 commit 紀錄本身就能看出我做了哪些事、順序是什麼。

主要參考的資料有：

- pytest 官方文件（入門、參數化測試、暫存檔的用法）
- pytest-cov 官方文件
- GitHub Docs 中關於用 Actions 建置與測試 Python 專案的說明
- 課堂上軟體測試章節的投影片，特別是邊界值分析的部分

使用的工具是 Python 3.11、VS Code、Git 和 GitHub。

## 五、可能遇到的問題及處理方式

我比較擔心的是不知道測試該寫哪些情況。我的想法是用上課教的邊界值分析：等第有 90、80、70、60 四個門檻，每個門檻都測「剛好達到」和「差一分」，再加上負數、超過 100 這種不合理的分數。

舊程式有些函式會直接讀檔案，可能不太好測。我查到 pytest 有 tmp_path 可以在測試時臨時建檔，應該可以解決；如果還是不好測，就把函式拆小一點。

修 bug 時也有可能改到其他地方。所以每改一次就重跑全部測試，而且每個階段都有 commit，真的改壞了還能退回去。

GitHub Actions 的設定檔是 YAML，縮排錯一格就不能跑，我對它也不熟。我會先從官方的 Python 範本開始改，出錯就看 Actions 頁面上的紀錄一步一步查。另外，本機會過但 GitHub 上失敗也是有可能的，所以會用 requirements.txt 寫清楚要裝哪些套件，並在幾個不同的 Python 版本上都跑一次。

如果時間不夠，至少會完成「補測試、修 bug、基本的 Actions」這三件事，多版本測試和覆蓋率門檻就當作有餘力再做的部分。
