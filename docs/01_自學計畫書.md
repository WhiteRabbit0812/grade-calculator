## 一、主題與學習動機

大一程式設計課時，我寫過一個「成績計算小工具」：讀取 `姓名,分數` 的 CSV 檔，算出每個人的等第（A～F）、GPA 和全班平均。當時我只用幾筆資料手動執行，看起來結果正確就交出去了，從來沒有寫過測試。

上軟體工程課講到軟體測試與持續整合（CI）時，老師提到「沒有測試的程式碼，就是不知道哪裡壞掉的程式碼」。我回頭看這個舊程式，發現自己其實不能確定它在各種情況下都正確，例如 60 分到底算不算及格、檔案有空白行會不會當掉。

因此我想用這個自己寫過、規模小、看得懂的程式當練習對象，實際體驗：

1. 怎麼為「已經寫好」的程式補測試；
2. 測試能不能真的找出我自己沒發現的 bug；
3. 怎麼讓測試在每次上傳程式碼時自動執行，而不是靠記得手動跑。

## 二、想回答的問題／預期達成的目標

**想回答的問題**

1. 對一個看起來「能跑」的程式補單元測試，能找到多少原本沒發現的錯誤？
2. 測試覆蓋率（coverage）達到多少才算夠？覆蓋率高是否就代表程式沒問題？
3. GitHub Actions 要怎麼設定，才能在 push 或開 Pull Request 時自動跑測試？

**預期達成的目標**

| 目標 | 可驗證的標準 |
|---|---|
| 學會 pytest 基本用法 | 能寫一般測試、參數化測試（`parametrize`）、例外測試（`pytest.raises`） |
| 為舊程式補測試 | 每個函式至少都有測試，包含邊界值與錯誤輸入 |
| 修正測試找到的 bug | 所有測試通過 |
| 分析覆蓋率 | 使用 pytest-cov，行覆蓋率達 90% 以上，並說明沒覆蓋到的部分 |
| 建立自動化測試 | GitHub Actions 在 push／PR 時自動執行，且覆蓋率低於 90% 時讓檢查失敗 |

## 三、學習方法與使用資源

**學習方法**

1. 先讀文件、跟著官方範例做一次，再套用到自己的程式。
2. 先寫測試、記錄「修正前」的失敗結果，再修改程式，最後比較前後差異（保留學習證據）。
3. 每完成一個階段就 `git commit` 一次，用 commit 歷史記錄學習過程。
4. 每週寫一小段學習紀錄（做了什麼、卡在哪、怎麼解決）。

**使用資源**

- pytest 官方文件：Get Started、How to parametrize、How to use temporary directories (`tmp_path`)
- pytest-cov 官方文件
- GitHub Docs：「Building and testing Python」、「Workflow syntax for GitHub Actions」
- 課堂投影片：軟體測試（黑箱測試、邊界值分析）章節
- 工具：Python 3.11、VS Code、Git、GitHub

## 五、可能遇到的問題及處理方式

| 可能的問題 | 處理方式 |
|---|---|
| 不知道測試要寫哪些情況 | 參考課堂教的邊界值分析，對每個分數門檻（90／80／70／60）測「剛好」與「差 1 分」 |
| 舊程式不好測（例如直接讀檔案） | 使用 pytest 的 `tmp_path` 建立暫存檔；必要時把程式拆成較小的函式 |
| 修 bug 時不小心改壞其他功能 | 每次修改都重跑全部測試，並用 Git 保留每個版本，壞掉可以回復 |
| GitHub Actions 的 YAML 寫錯、看不懂錯誤訊息 | 先複製官方 Python 範本再慢慢修改；看 Actions 頁面的 log 逐步除錯 |
| 本機能過、GitHub 上卻失敗（環境不同） | 用 `requirements.txt` 固定需要的套件；在 workflow 測多個 Python 版本 |
| 時間不夠 | 以「補測試＋修 bug＋基本 Actions」為最低目標，多版本測試、覆蓋率門檻為加分項目 |
